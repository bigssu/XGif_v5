# 출시 후보 강화 계획과 검증 기록

이 문서는 1차 리뷰 이후의 출시 전 강화 작업을 기록한다. 기존 작업 트리 변경은
유지하며 외부 배포, 실제 설치, 서명 키 변경은 수행하지 않는다. 기존 dist 산출물은
보존하고 별도 작업 디렉터리에 새 실행 파일과 설치 패키지를 생성한다.

## 수용 기준

1. 이미지 clone/snapshot이 변경되지 않은 압축 프레임 전체를 해제하지 않는다.
   원본·복제본 편집 독립성, 재생 프레임 창의 decoded 상주량을 회귀 테스트한다.
2. 비디오 probe/decode 중 Cancel과 deadline이 실제 자식 프로세스를 중지하고
   thread/process/handle을 정리한다. GIF 취소가 부분 로드 성공으로 바뀌지 않는다.
3. 설정·다운로드·설치·변환 실패가 기존 정상 데이터를 훼손하지 않는다.
   임시 경로는 해당 작업만 소유하며, 명시적 마이크 요청과 종료 상태를 보존한다.
4. 취소·닫기·저장·Undo 혼합 시나리오 및 불완전/손상 입력을 테스트한다.
5. 전체 pytest, Ruff, compileall, diff 검사와 설치된 도구를 이용한 isolated 빌드,
   생성된 EXE의 CLI/GUI 스모크 검증을 수행한다. 실제 설치는 하지 않는다.
6. 코드 검토자와 아키텍처 검토자의 독립 재검토 후 미해결 결함과 장치·서명·환경
   검증 한계를 명시한다. 모든 장치/환경의 무결함을 주장하지 않는다.

## 구현 순서

- 기존 증거와 배포 구성을 확인하고 재현 테스트부터 추가한다.
- decoder 취소, 메모리 수명, 파일 보존, CLI/패키징을 파일 소유권별로 수정한다.
- GUI와 worker 경계를 통합하고 전체 테스트 및 실제 생성 미디어를 검증한다.
- 새 빌드·패키지와 검증 결과, 해시, 남은 출시 조건을 이 문서에 기록한다.

## 현재 기준선

- 1차 수정 후 415개 테스트 통과, Ruff/compileall/CLI help 통과.
- 이전 dist 실행 파일·설치본은 현재 수정본의 검증 근거로 사용하지 않는다.
- 설치된 빌드 도구: PyInstaller 6.20.0, hooks 2026.5, Inno Setup 6.
- 신규 의존성 추가 없이 기존 설치 도구와 표준 라이브러리를 우선한다.

## 적용 결과

- 설정 저장, 다운로드, FFmpeg 설치와 변환 출력에 임시 파일·원자적 교체 및
  실패 복구를 적용했다. 손상 설정, `%` 포함 경로, 다운로드 중단·길이 불일치,
  덮어쓰기 실패에서 기존 정상 파일을 보존하도록 검증했다.
- 비디오 probe/decode 취소와 시간 제한이 자식 프로세스를 종료·회수한다.
  GIF 로드 취소를 부분 성공으로 처리하지 않으며, 종료 후 대기 중인 UI 콜백을 차단한다.
- 압축된 프레임 clone이 전체 이미지를 디코딩하지 않도록 했다. 현재 이미지가
  이미 수정된 경우에는 그 픽셀을 복사하여 원본·복제본의 편집 독립성을 유지한다.
  썸네일·저장·스냅샷의 임시 디코딩과 프리뷰 캐시 수명을 제한했다.
- 저장 중 새 파일·닫기·Undo 전환과 재생 프레임 선택을 보강했다.
  오디오 일시정지, 녹화 취소·재시도, countdown 취소와 CLI 숫자 검증을 수정했다.
- 자동 하드웨어 인코딩의 초기화·지원 오류에는 CPU로 한 번 재시도한다.
  명시한 인코더, 시간 초과, 입력·디스크·권한 오류에는 이 재시도를 적용하지 않는다.
  원래 인코더 종료 코드와 오류를 보존한다.
- GUI `XGif.exe`와 콘솔 `XGif-cli.exe`를 함께 빌드하고 설치 패키지에 포함한다.
  DXCam의 동적 NumPy 네이티브 모듈을 명시적으로 수집한다.
- DXCam 사전 준비는 잠금 안에서 공유 카메라 생성만 수행한다. 준비 단계의
  start/grab/stop을 제거해 실제 녹화 시작과의 충돌 및 첫 프레임 소비를 방지했다.

## 성능 증거

- 합성 300개 RGB 256×144 프레임 복제: 기존 방식 0.121406초 → 0.004412초.
  복제로 인해 디코딩 상태가 된 원본 프레임은 300개 → 0개였다.
  이는 해당 합성 경로의 측정이며 전체 앱 RSS나 실제 녹화 FPS 향상률이 아니다.
- 1,000개 지연 로드 프레임 전체 선택 후 2,000회 재생 tick 회귀 시험에서
  원본 decoded 프레임은 최대 5개였다. 대규모 편집 결과물과 Undo 스냅샷까지
  포함한 총 메모리 사용량의 상한을 보장하지는 않는다.

## 남은 출시 조건

- 수동 GUI 검증은 사용자의 Escape 입력으로 중단됐으며 재개하지 않았다.
  자동화 회귀 테스트를 수동 화면·장치 검증 완료로 해석하지 않는다.
- 설치 프로그램은 컴파일만 검증한다. 실제 설치·업그레이드·제거,
  다중 모니터/HDR·장시간 녹화·실제 마이크·다른 GPU/드라이버는 별도 수용 시험이 필요하다.
- 산출물은 서명하지 않았다. 외부 FFmpeg/FFprobe가 필요하며 이번 작업에서
  다운로드·설치는 실행하지 않았다. 다운로드 길이/압축 검사와 선택적 SHA-256 지원은
  배포 서버의 진위를 보장하는 고정 체크섬 검증을 대체하지 않는다.
- GIF의 Pillow 단일 프레임 디코딩은 호출 중 강제 중단하지 않으며 프레임 사이에서 취소한다.
- 전체 테스트·빌드 통과는 모든 환경에서의 무결함 또는 외부 출시 승인을 의미하지 않는다.
