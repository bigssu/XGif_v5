## Top 3 Priority Fixes

1. **Editor dialogs/menus leak hardcoded Korean (Copywriting 2/4, blocks P5).**
   *User impact:* English-locale users see mixed Korean/English UI across every editing dialog and most editor warnings; layout cannot be verified for string expansion.
   *Concrete fix:* Route the ~40 `label=`/`title=` literals in `editor/ui/dialogs/*` and the ~28 Korean `wx.MessageBox(...)` calls in `editor_main_window_wx.py` (e.g. `:1155`, `:1198`, `:1269`, `:1829`) through `translations.tr("...")` with new keys mirroring the existing `en.json`/`ko.json` `editor` section. Then add a static test (extend `test_ui_design_system_contracts.py`) asserting no `[가-힣]` inside string literals in `editor/ui/**/*.py` outside an allowlist — same guardrail the audit doc's P6 specifies.

2. **Editor main window is hard-pinned to 1008×840 (Spacing 2/4, P0 "Fixed-Size" unresolved).**
   *User impact:* On a 1366×768 laptop or at 150% Windows scaling the editor cannot fit; this is the largest remaining responsiveness regression and directly contradicts the audit doc Stop Condition ("Fixed-size dialog constraints are removed or explicitly justified").
   *Concrete fix:* In `editor/ui/editor_main_window_wx.py:333-334`, replace `SetMinSize((1008,840)); SetSize((1008,840))` with a content-driven minimum (a true interaction floor, e.g. `(880, 620)`) and an initial size clamped to `wx.Display(...).GetClientArea()` minus margin — the exact pattern already proven in `ThemedDialog.fit_to_content` (`theme.py:424-444`). Add a `GetBestSize()`/min-size instantiation test per P6.

3. **Recorder/editor icon-button primitives not unified; `FormSection`/`FormRow` missing (P1 acceptance not met).**
   *User impact:* Three owner-drawn button implementations (`FlatButton` recorder legacy, `CommandButton` shared, `FlatIconButton` editor) drift on hover/press/disabled/focus behavior; settings/editor dialogs still render as old `StaticBox` form-sheets, the exact "dialogs feel older than the editor" symptom P1 set out to kill.
   *Concrete fix:* (a) Migrate `editor/ui/icon_toolbar_wx.py FlatIconButton` callers to the shared `design_system` icon path (or make `FlatIconButton` a thin subclass over `CommandButton(icon_type=...)`), and delete the now-unused `FlatButton` from `capture_control_bar.py:17` once no longer referenced. (b) Add the planned `FormSection`/`FormRow` to `ui/design_system.py` and refactor `settings_dialog.py:67-162` and at least one `editor/ui/dialogs/*` to use them, satisfying the P1 acceptance "Dialog section spacing and action bars are consistent."

## Detailed Findings

### Pillar 1: Copywriting (2/4)

Strong on the migrated surfaces, unmigrated everywhere else.

- **Recorder:** every visible string/tooltip is `tr()`-routed — `capture_control_bar.py:746-771` `retranslateUi` re-translates all combos/tooltips; quality combo rebuilt with `tr('high'/'medium'/'low')` (`:417`, `:757-759`).
- **Dependency flows:** fully i18n — `dependency_dialogs.py` uses `tr('dep_*')`, `tr('cupy_*')`, `tr('ffmpeg_*')` throughout; only residual raw strings are progress detail messages like `f"FFmpeg 다운로드 중...\n…"` (`:531`, `:535`, `:578`) and one frozen-mode `wx.MessageBox` Korean string (`:628-629`) — narrow but real P5 leftovers.
- **Editor (the bulk of the debt):** ~40 hardcoded Korean `label=`/`title=` in `editor/ui/dialogs/*` — e.g. `crop_dialog_wx.py:18 title="이미지 자르기"`, `:37 "크롭 영역"`, `:112 "적용"`, `:118 "취소"`; `resize_dialog_wx.py:27,52,59,96`; `pencil_dialog_wx.py:18,49,118`; `sticker_dialog_wx.py:45,82,255,261`; `text_dialog_wx.py:17,30,45`; `speed_dialog_wx.py:19,40`; `effects_dialog_wx.py:102,212,229`; `help_dialog_wx.py:28,87,270,311`.
- **Editor warnings:** ~28 Korean `wx.MessageBox` in `editor_main_window_wx.py` (`:1155 "유효하지 않은 프레임 인덱스입니다."`, `:1198/1537/1643/… "메모리가 부족하여 작업을 수행할 수 없습니다."`, `:1269/1276/… "GIF 파일을 먼저 열어주세요"`, `:1829 "저장할 프레임이 없습니다."`, `:1998 "최근 파일 목록이 삭제되었습니다."`) plus `frame_list_widget_wx.py:552`, `inline_toolbars/pencil_toolbar_wx.py:115-125`.
- Empty canvas copy is English-only literal (`canvas_widget_wx.py:340-341 "No frame loaded" / "Open a GIF to preview edits here"`) — not `tr()`-routed, so it will *not* localize to Korean (inverse of the editor-dialog problem). Audit doc explicitly called this out under P1; still open.

### Pillar 2: Visuals (3/4)

- **P0 "text glyphs as icons" — resolved for the recorder.** `ui/design_system.py:37 draw_symbol_icon` renders record/stop/play/pause/cursor/region/settings/help/gpu as monoline/fill vector paths in a `GraphicsContext`. `capture_control_bar.py` builds buttons with `icon_type=` (`:467 gpu`, `:478 record`, `:489 pause`, `:501 settings`, `:512 help`) and `RailIcon(self,"cursor")`/`RailIcon(self,"region")` (`:436`, `:447`). State transitions swap icon+semantic color coherently (`set_recording_state` `:780-808`). The banned-symbol contract (`test_ui_design_system_contracts.py:29-39`) locks this.
- Primary action focal point is clear: REC/STOP is the only icon+label button with bold weight (`design_system.py:186 bold=bool(label and icon_type)`) and a saturated semantic fill (`Colors.REC_READY` → `Colors.ACCENT` when recording).
- Editor toolbar discoverability improved beyond tooltips: visible `ToolbarGroupLabel`/`ToolbarGroupCard` with per-group i18n labels (`icon_toolbar_wx.py:268-279`, contract `:62-98`) — this is Phase-4 work landed early.
- **Why not 4:** the audit's P1 acceptance "Recorder and editor use the same icon button primitives" is unmet. Three parallel owner-drawn stacks: legacy `FlatButton` (`capture_control_bar.py:17`, still defined), shared `CommandButton` (`design_system.py:144`), editor `FlatIconButton` (`icon_toolbar_wx.py:48`). They re-implement hover/press/disabled/cache independently — visual relatedness without true systematization, exactly the P0 "look related but not fully systematic" symptom.

### Pillar 3: Color (4/4)

- Semantic token routing is essentially complete on the audited high-visibility surfaces. `Grep wx\.Colour\(\d+,\d+,\d+` → **0 hits** in `editor/ui/editor_main_window_wx.py`, **0** in `ui/capture_control_bar.py`, **0** in `ui/main_window.py`. All color comes from `ui/theme.py Colors` (the 92 `wx.Colour(...)` there are the palette definitions — correct single source).
- `ui/theme.py` defines a coherent semantic set incl. status (`SUCCESS/WARNING/DANGER/INFO`), recorder states (`REC_READY/REC_RECORDING/REC_PAUSED`), and editor-specific accents — `StatusPill._PALETTE`/`InlineBanner._BORDER` consume them (`design_system.py:417-452`).
- Native dark-continuity break (audit P0: native `wx.ProgressDialog` in `dependency_dialogs.py`) is **fixed** — replaced by `ThemedProgressDialog(ThemedDialog)` with an owner-styled `wx.Gauge`; contract asserts `"wx.ProgressDialog(" not in dependency_dialogs` (`test_ui_design_system_contracts.py:59`).
- Only residuals: two intentional `wx.Colour(40,40,40)`/`wx.Colour(220,220,220)` for a read-only command textbox (`dependency_dialogs.py:345-346`, terminal-style affordance) and DC hex strings in `theme.py:94-98` (centralized, single source). Both acceptable — not drift. Score held at 4/4.

### Pillar 4: Typography (3/4)

- `ui/` is clean: `Grep wx\.Font\(` returns only `theme.py:241,244` (the `Fonts.get_font` primary + Segoe UI Variable→Segoe UI fallback construction mandated by CLAUDE.md). Every recorder/dialog widget uses `Fonts.get_font(Fonts.SIZE_*, bold=…)`.
- `design_system.py` is disciplined: `SIZE_DEFAULT` for buttons, bold only for icon+label primaries (`:186`), `StatusPill` label bold (`:428`).
- **Why not 4:** `editor/ui/` still constructs 5 ad-hoc `wx.Font(` (`icon_toolbar_wx.py:1`, `icon_utils_wx.py:4`) for icon glyph rendering — low user-visible risk but off the token path. More materially, the editor dialogs (`editor/ui/dialogs/*`) set labels without a consistent `SIZE_*` tier or weight strategy, so heading/body hierarchy depends on `StaticBox` chrome rather than type scale — the prior pass already flagged this ("broader dialog typography remains for a later pass"); unchanged.

### Pillar 5: Spacing (2/4)

- Centralization wins: `CommandButton._sync_min_size_to_content` (`design_system.py:262-277`) derives button width from text+icon+token padding instead of magic constants; recorder/dialog buttons all flow from this. `Spacing`/`Sizes` token classes exist in `theme.py:159-217`.
- Save dialog responsiveness improved per P3: was fixed `900x550` (prior pass + audit P0), now `SetSize((860,560))` + `SetMinSize((720,520))` (`save_dialog_wx.py:121-122`), contract-locked (`test_ui_design_system_contracts.py:48-50`). Settings min reduced to `400x420` with `RESIZE_BORDER` (`settings_dialog.py:33,40`).
- **Why 2 (down from holistic 3):** the audit's P0 "Fixed-Size Layouts Limit Responsiveness" is only half-addressed. The single largest surface — the editor shell — is still hard-pinned: `editor_main_window_wx.py:333-334 SetMinSize((1008,840)); SetSize((1008,840))` (audit doc cited "editor initialized around 1008x840 minimum"; unchanged). Multiple editor dialogs keep fixed `SetMinSize((300,300))` previews (`sticker_dialog_wx.py:71`, `effects_dialog_wx.py:126`), `help_dialog_wx.py:40 (560,480)` / `:275 (440,320)`. Magic-pixel `SetMinSize((NNN,-1))` label columns still pervasive in `settings_dialog.py` and editor dialogs. On a full-surface holistic view this is the weakest pillar; on the prior pass's editor-action-button slice it held at 3.

### Pillar 6: Experience Design (4/4)

- Feedback primitive set exists and is correct: `StatusPill` (5 semantic states), `InlineBanner` (info/warning/error/success with bordered repaint), `ThemedProgressDialog` (Update/Pulse, optional themed Cancel) — `design_system.py:414-544`. All test-locked.
- Themed progress is wired into the real install flows: `_install_ffmpeg` and `_install_dxcam` use `ThemedProgressDialog(... wx.PD_CAN_ABORT/PD_AUTO_HIDE)` and report via themed UI (`dependency_dialogs.py:513-518`, `:635-641`).
- Thread-safety as UX correctness (per `.claude/rules/wx-patterns.md`): background→GUI consistently marshaled with `wx.CallAfter` — `dependency_dialogs.py:455,457,459,658`; `main_window.py` 17 `wx.CallAfter` sites incl. progress callback (`:111`). No background-thread direct GUI mutation found in the audited paths. Timers cleaned in `EVT_WINDOW_DESTROY` (`capture_control_bar.py:248`, `save_dialog_wx.py:93`).
- Empty state present: `canvas_widget_wx.py:328 _draw_empty_state` draws a centered card with title/detail when no frames.
- Destructive/disabled handling: pause disabled until recording (`capture_control_bar.py:496,816-818`); `_install_ffmpeg` disables parent during install to prevent reentrancy (`dependency_dialogs.py:564-583`).
- Held at 4/4. The only soft spot is *adoption breadth*, not correctness: `main_window.py` still surfaces recoverable validation via 13 `wx.MessageBox(tr(...))` modals and a plain `StaticText` status (`:268`) rather than the new `InlineBanner`/`StatusPill`. That is a Phase-2/5 adoption task; the primitives and the wiring discipline are sound, so the pillar stays at ceiling while the roadmap table records the unfinished rollout.
